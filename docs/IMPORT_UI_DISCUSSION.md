# 导入页（`/import`）主卡：讨论记录与状态

> **状态**：讨论与历史取向记录；**正式 `/import` 行为以仓库代码为准**。  
> 静态对照页：**`/import/mock`**（仅 UI 示意，无保存、无抓取）。

---

## 1. 名词与行为（对齐代码）

### 「正文」

- 用户可见主卡标题；保存到 **`articles.original_text`** 的定稿编辑区（`cleanedText`）。
- 历史上曾用文案「将保存的正文」，已统一为「正文」以降低冗长感。

### 「来源稿」（`rawPastedText`）

- **含义**：整理前的输入稿，用于再跑 **`parseArticleFromRawInput`** 生成上方定稿。
- **典型来源**：
  - **链接抓取**：优先用接口 **`raw_text`**；若无，则用 **`cleaned_text` 兜底**（此时与定稿可能一致，**不一定是「脏稿」**）。
  - **从剪贴板读取**：剪贴板整段（从网页复制时**常**带广告/页脚，**不保证**）。
  - **Chrome 插件**：插件传入的正文草稿。
- **不是**：用户必须先打开来源稿再粘贴；剪贴板按钮会写入来源稿并生成定稿。
- **同步**：来源稿修改后约 **400ms** 防抖再跑 **`parseArticleFromRawInput`**，写回 **`cleanedText`**（并可能补标题等）。

### 「重新整理」（**已移除，2026-05-13**）

- **曾义**：用当前 **`rawPastedText`** **立即**再跑一次 **`parseArticleFromRawInput`**（与防抖相同逻辑，无额外清理）。
- **移除原因**：多数场景由来源稿防抖覆盖；减少主路径按钮与认知负荷。

### 剪贴板 vs 直接贴定稿

- **网页 messy 全文**：更推荐 **「从剪贴板读取」**（先来源稿再解析）。
- **已很干净**：可直接在 **「正文」** 编辑/粘贴。

---

## 2. 产品讨论结论（备忘）

- **认知负荷**：主路径应「少猜」；「来源稿」对多数用户偏进阶，故默认折叠。
- **去掉来源稿**：会削弱「原文 ↔ 定稿」对照；当前保留折叠 **「来源稿（可选）」**。
- **Mock 对照**：`/import/mock` 中 **B 栏**为历史草案示意（三按钮同排、白话「原始全文」、第二按钮长文案等）；**长文案不采纳**。

---

## 3. 当前实现摘要（`/import`）

1. **主卡标题**：**「正文」**。
2. **按钮**：textarea 下方同一行 **「从剪贴板读取」**、**「保存文章」**（无底部重复保存行）；**无**「重新整理」。**默认链接导入**时「从剪贴板读取」为 **secondary** 视觉；**手动粘贴**模式下该按钮为主色（**primary**），与保存并列时突出剪贴板主路径。
3. **解析触发**：**来源稿（`raw`）** 变更防抖调用 **`parseArticleFromRawInput`**；直接编辑「正文」不自动重跑解析（与历史行为一致）。
