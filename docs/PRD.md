# German Reading Coach — Product Requirements Document

## 1. 产品定位

German Reading Coach 是一个面向德语学习者的**个性化阅读学习工具**，**当前产品重心**为**真实德语文章**（尤其**新闻**）的**阅读训练**。用户可以输入文章链接或粘贴正文；系统按用户所选水平生成阅读辅助材料，包括：原文高亮、分级词汇与表达解释、语法点分析、中文/德语解释、例句、阅读问题、总词库、总语法库及后续复习能力规划。

### 1.0 目标用户与核心价值（文档检查点）

- **目标用户**：**中文母语**者学习**德语**；水平侧重 **A2–B2**，尤其 **B1 / B2** 面向**新闻/真实语料**的阅读阶段。**解释语言、母语与目标语言**的未来组合见 **§1.5.6**（当前 MVP 仍以中文解释 + 德语学习为主）。
- **核心目标**：用户**导入真实德语文章**后，系统在**通读前/通读中**标出**理解主旨与关键细节**所最需要的**词汇、表达与语法**；用户结合释义后，应能**大致读懂文章主旨与关键细节**，而不必频繁停读查词。
- **与「翻译工具」区分**：免费翻译工具侧重**单篇即时看懂**；本工具侧重**通过每一篇真实阅读积累词汇与语法能力**（见下「核心定位」）。

**核心定位：**

- 免费翻译工具帮用户**看懂这一篇文章**；
- German Reading Coach 帮用户**通过每一篇文章真正提高德语阅读能力**。

### 1.1 产品形态

German Reading Coach 的**核心不是**单一手机 App，也**不是**只做一款独立 Chrome 插件；而是一个**支持多入口导入**的德语阅读学习系统。

- **Web App 是产品主体**，负责：
  - 用户登录（Supabase Auth）
  - 保存文章、总词库、总语法库
  - 保存词汇出现记录、语法出现记录
  - 展示阅读页、词库页、语法库页
  - 后续接入 **OpenAI API** 分析文章
  - 后续支持复习、支付与商业化能力
- **Chrome 浏览器插件**是**桌面端导入入口**，负责：
  - 在桌面 Chrome 中读取当前网页**标题、URL、正文**
  - 清理广告、导航、图片说明、推荐阅读等**非正文**内容
  - 将文章**发送到 Web App** 保存（同一用户账号）
  - 保存成功后跳转到 **`/articles/[id]`**
  - 可提供浏览器按钮或右键菜单 **「导入到 German Reading Coach」**，减少用户手动全选、拖动、复制全文的操作成本
- **手机端入口**包括但不限于：
  - 手机浏览器访问 **Web App**
  - **粘贴正文**或 **URL** 导入（与 Web 共用 **`/import`** 等流程）
  - 未来 **PWA**
  - 未来**系统分享**导入
  - 未来 **iOS / Android Share Extension**

### 1.2 数据同步原则

**Supabase** 是**统一云端数据库**。无论文章从 **Web、插件或未来手机入口**导入，最终都写入**同一套**业务表（在 **`user_id` / `profiles.id`** 维度归属同一账号）：

- **`profiles`**
- **`articles`**
- **`vocabulary_items`**、**`vocabulary_senses`**、**`vocabulary_occurrences`**
- **`grammar_items`**、**`grammar_occurrences`**

所有业务数据行均须带 **`user_id`**（**`profiles`** 以 **`id = auth.uid()`** 对应用户），与 RLS 一致。

因此：

- 桌面 Chrome **插件**导入的文章，手机登录**同一账号**后也能看到
- **手机端**导入的文章，桌面 **Web App** 也能看到
- 词库、语法库、掌握状态、忽略状态等应**跨设备同步**
- **导入方式可以多种，学习数据只有一套**（单用户单一真相源）

### 1.3 商业化方向

对外的产品叙事可以是：**「帮助德语学习者从真实网页文章中学习词汇和语法的浏览器插件 + Web App 学习系统」**。收费**不应只绑定插件本身**，而应基于**账号与使用额度**：

- 插件可**免费安装**；用户**登录 Web App 账号**后使用后端能力
- **免费用户**可有文章数量等额度限制
- **付费用户**拥有更多文章导入额度、**AI 分析**、长期词库/语法库与复习等能力

### 1.4 开发路线调整（当前优先级）

1. 完成 **Web App** 的文章保存与阅读闭环（进行中）
2. 确保 **`/import`** 可将文章保存到 **Supabase `articles`**
3. 确保 **`/articles/[id]`** 真实文章页读库展示
4. 确保 **`/dashboard`** 可读取最近文章，**`/articles`** 可分页查看全部已保存文章
5. **Chrome 插件 MVP**：提供工具栏按钮 / 右键菜单，将当前网页中用户已可见的文章内容发送到 Web App 的 **`/import`** 预填草稿
6. 后续接入 **OpenAI** 分析正文
7. 后续再考虑**手机分享导入**与 **PWA**
8. **自动登录抓取**保留为**后续评估项**，**不作为当前 MVP** 承诺

### 1.4.2 导入体验路线与合规边界（2026-05 检查点）

**边界**：产品不实现绕过付费墙、登录墙或订阅限制的抓取方式。对于会员站、需登录站点或拒绝服务端抓取的站点，导入能力只处理**用户已经合法可见**的正文：用户手动粘贴、浏览器插件读取当前已展示页面、或系统分享用户选中的文本。服务端 URL 抓取仅用于公开可访问页面与合理的网页解析，不承担绕过访问控制。

**短期（Web App）**

- **`/import`** 保持「链接导入 / 手动粘贴」双模式；当服务端抓取失败时，在 URL 输入框附近给出轻提示，引导用户改用手动粘贴。
- 已支持 **「从剪贴板读取」** 按钮：用户在手机或桌面已复制正文后，一键填入手动粘贴区并触发现有清理逻辑，减少“点输入框 → 粘贴”的步骤。该能力仍需用户主动授权剪贴板读取，失败时回退手动粘贴。

**中期（桌面 Chrome 插件）**

- 提供插件按钮与右键菜单 **「导入到 German Reading Coach」**。
- 插件在当前网页上下文中读取用户**已经能看到**的标题、URL、正文，并通过 `/import?chromeDraftId=...` 打开 Web App 预填草稿；提取时应扫描页面可见的大字号 / 粗体文字块，优先选择视觉大标题与正文段落，并过滤 / 截断 newsletter、相关阅读、作者简介、分享与评论等非正文块。
- 重点解决服务端抓取受限、需要浏览器登录态、手动全选复制困难等场景；不绕过页面权限，不自动破解付费墙。

**后期（手机端）**

- 优先做 **PWA / 系统分享导入**：接收 URL、标题、用户选中文本；若仅收到 URL，则走现有 `/import` 链接导入并在失败时引导粘贴。
- 对于手机上“全文选择困难”的问题，优先支持**选中文本分享**与**剪贴板读取**；完整的一键正文提取需评估 **iOS Safari Extension**、**Android 浏览器扩展**或系统 Share Extension，作为后续较重投入。

### 1.4.1 当前已实现（Phase 2.5 Web，截至文档更新日）

- **Supabase Auth**：邮箱密码登录、`profiles`。
- **导入**：**`/import`** 将清洗后的正文写入 **`articles`**，跳转 **`/articles/[id]`**（标题识别与正文清理规则见 **`parseArticleFromRawInput`** / **`cleanArticleText`**）。
- **真实文章阅读**：**`/articles/[id]`** 读库正文；用户可**手动标注词汇与语法**；数据写入 **`vocabulary_*` / `grammar_*`**（**anon key + RLS**，须表级 **GRANT**）；**掌握 / 忽略 / 恢复** 可持久化；刷新或再次进入文章页可恢复侧栏数据。语法卡片详情提供 **「外部深入解释」**：一键生成固定模板 **Prompt**、写入剪贴板、可选打开 ChatGPT / Claude / Gemini / DeepSeek 网页（**不**调用本应用 AI API、**不**写入数据库、**不**自动填写或发送外部站点输入）；点击后直接跳转，并在页内提示“点击后会自动复制深度学习 Prompt，可在外部页面直接 `Ctrl+V` 粘贴发送”（如浏览器拦截新页会提示检查弹窗设置）。复制失败时提示用户手动复制。**词汇卡片**提供同族 **「外部深入解释」**（词条、lemma、原文形式、词性/类型、义项解释、上下文句、文章标题、水平与词条估计等级等写入模板；行为约束与语法一致）。**Phase 4.1**：文章页支持**删除文章（v1）**，确认后删除该文章及其 `vocabulary_occurrences` / `grammar_occurrences`，并保留长期 `vocabulary_items` / `vocabulary_senses` / `grammar_items`。
- **Phase 3.14（AI 调用约束）**：已生成并保存的阅读辅助内容应稳定保留；**刷新、切换 Tab、离开再进入**不得自动调用 **`/api/analyze-article`** 或单项 enrich。仅当**解释缺失**时显示 **「补充 AI 解释」**；**已有完整解释**时**不在**普通词汇/语法卡片提供 App 内「重新生成解释」（避免误点与重复 API 成本），深入需求用 **「外部深入解释」** 外链。**全文分析**在**已有保存的词汇/语法或摘要/阅读问题**时，主按钮为 **「重新分析本文（会再次调用 AI）」**，点击前须确认 **「这会再次调用 AI，并可能产生费用。确定重新生成吗？」**；**新预览不自动覆盖**已保存数据，用户可先在预览区删除不需要的 AI 候选或标记学习状态，**用户确认保存**后再写入；失败时保留旧内容。
- **真实 OpenAI 与保存（Phase 3.1–3.4）**：**`POST /api/analyze-article`** 返回结构化分析；阅读页**预览**后，AI 词汇 / 语法先作为候选清单展示，用户可在保存前删除单个候选，或将候选状态设为学习中 / 已掌握 / 暂忽略；点击一键保存后，仅保留候选写入 **`vocabulary_*` / `grammar_*`**（**`source = ai`** 等，带所选 `mastery_status`），并将 **摘要 / 阅读问题** 写入 **`articles`**（**`summary_*`、`reading_questions`**，须 **`007_article_analysis_fields.sql`**）。环境变量 **`OPENAI_API_KEY`** 仅服务端，**禁止** `NEXT_PUBLIC_*`。
- **Chrome 插件 MVP**：`browser-extension/chrome-mv3` 已提供桌面端导入入口：工具栏按钮 / 右键菜单读取当前页面可见标题、URL、来源与正文，打开 `/import` 并预填草稿；插件会扫描页面可见的大字号 / 粗体文字块，优先选择视觉大标题，提取正文段落并跳过 newsletter、相关阅读、作者简介、分享与评论等非正文块，`/import` 清理器继续做尾部截断兜底。多语言扩展见 **§1.5**。**Phase 3.8** 已完成总词库/总语法接库与单项状态管理，后续再扩展复习与编辑能力。

### 1.5 多语言与英语扩展（产品愿景）

当前 MVP 以**德语学习**为主，但底层逻辑可抽象为**多语言阅读学习系统（Reading Coach）**：**German Reading Coach** 为其德语版本。

#### 1.5.1 多语言扩展方向

未来同一套能力可覆盖多种目标语言，包括但不限于：

- **真实文章导入**（Web / 插件 / 手机等多入口）
- 根据用户水平**解释词汇、短语、语法与表达**
- **个人文章库**、**个人词库**、**个人语法库**
- **掌握 / 忽略**等状态与**跨设备同步**
- 后续 **AI** 根据用户历史**调节解释强度**

#### 1.5.2 英语扩展方向（优先）

**英语**是优先考虑的扩展语言（潜在用户基数更大）。英语版的学习辅助除单词释义外，还应覆盖例如：

- **Phrasal verbs**（短语动词）
- **Collocations**（搭配）
- **Idioms**（习语）
- **Preposition patterns**（介词模式）
- **Tense and aspect**（时与体）
- **Passive voice**（被动语态）
- **Conditionals**（条件句）
- **Relative clauses**（关系从句）
- **Academic vocabulary**（学术词汇）
- **News vocabulary**（新闻词汇）
- **Register and tone**（语体与语气）

#### 1.5.3 英语水平体系与考试参考

- **产品内部建议统一使用 CEFR**：**A1、A2、B1、B2、C1、C2**（与当前德语档位模型一致，便于跨语言复用）。
- **界面层**后续可增加常见考试或标准的**对照参考**（非替代 CEFR），例如：**IELTS**、**TOEFL**、**Cambridge English**、**TOEIC**、中国**四六级 / 考研英语**等；具体映射与展示以迭代为准。

#### 1.5.4 数据库后续扩展（仅文档）

后续多语言上线时，可考虑为业务表增加 **`language`** / **`target_language`** 等字段（详见 [`DATABASE.md`](./DATABASE.md) **§10.7**）。**当前阶段不修改数据库 schema**，仅在文档中记录方向。

#### 1.5.5 当前开发优先级（不变）

在完成德语 MVP 前，**不切换主线**。当前仍优先：

1. **真实文章页**手动词汇 / 语法标注（及后续持久化）
2. **词汇 / 语法持久化**到 Supabase
3. **OpenAI** 自动分析**德语**文章
4. **Chrome 插件 MVP**
5. **部署**（如 Vercel）
6. **后续再评估**英语版与多语言 **Reading Coach** 产品形态与排期

#### 1.5.6 用户语言模型（不写死单一母语）

**当前版本**的默认体验可理解为：**中文母语者**学习**德语**，**解释语言**以**中文**为主、**简单德语**为辅，主要材料为**德语新闻/长文**。产品需求**不应将上述组合写死**为唯一形态。

未来产品应显式支持（概念上，实现与库字段迭代见 **§1.5.4**、**`DATABASE.md` §10.7**）：

| 概念 | 含义（示例） |
|------|----------------|
| **`native_language`** | 用户母语或主要界面语言（如 **`zh`**、**`en`**） |
| **`explanation_language`** | 释义与讲解所用语言（如 **`zh`**、**`en`**） |
| **`target_language`** | 所学阅读语言（当前 MVP 为 **`de`**；扩展可为 **`en`** 等） |

示例配置（仅说明组合，非当前库字段承诺）：

- 中文用户学德语：`native_language=zh`，`explanation_language=zh`，`target_language=de`
- 中文用户学英语：`native_language=zh`，`explanation_language=zh`，`target_language=en`
- 英语用户学德语：`native_language=en`，`explanation_language=en`，`target_language=de`

## 3. 核心优势

- **不是翻译工具**，而是阅读学习工具。
- **原文高亮 + 右侧解释**，阅读流不被打断。
- **总词库长期累积**、**总语法库长期累积**。
- 系统记录用户**见过什么、掌握什么、忽略什么**。
- 根据用户**水平**和**掌握状态**决定下一篇文章中如何呈现辅助信息。
- 真实文章中的语法积累（例如统计某段时间内 **dass** 从句、被动态、关系从句等出现与掌握情况）。
- 用户可以**手动补充** AI 漏掉的词汇和语法。

## 4. 德语水平选择组件

支持 **A1、A2、B1、B2、C1、C2**。

**与 AI 分析的关系**：用户所选档位用于驱动 **Phase 3.1+** 真实 OpenAI 推荐的侧重点与数量策略，详见 **§13**；**Phase 3.0 Mock** 仅占位验证数据流。

**A2、B1、B2** 需要**视觉高亮**，并标注 **「推荐用于新闻阅读训练」**。

每个等级需要显示：

- 适合什么用户
- 系统会如何解释文章
- 简短说明
- **提醒**：这里的水平主要用于判断**阅读辅助强度**，不等于完整听说读写的 CEFR 水平

### 各等级说明（摘要）

| 等级 | 用户画像与系统行为（摘要） |
|------|---------------------------|
| **A1** | 入门，普通新闻通常太难。系统解释大量基础词，使用更多中文说明，尽量拆解句子。 |
| **A2** | 初级，可开始读简化文章。系统解释较多基础和中频词，提醒 Perfekt、Modalverben、可分动词、weil/dass 从句等。 |
| **B1** | 中级，适合开始读真实新闻。系统不再解释太基础的词，重点解释新闻高频词、抽象名词、动词搭配、从句、被动态、关系从句、介词格。 |
| **B2** | 中高级，适合普通新闻和专业话题。系统只解释较高级或文章理解关键的词，强调搭配、语体、抽象名词、隐含逻辑、复杂从句、Konjunktiv II、名词化、被动态组合。 |
| **C1** | 高级，主要关注隐含意思、语气、风格、精确表达和高级结构。 |
| **C2** | 精通，主要用于高级语言分析，不作为 MVP 核心目标。 |

## 5. 掌握状态

单词和语法均支持以下状态：

- `new`
- `learning`
- `familiar`
- `mastered`
- `ignored`

**显示规则（目标行为）：**

- **new**：完整解释。
- **learning**：简短解释 + 上下文。
- **familiar**：轻微高亮，点击后显示。
- **mastered**：默认不常驻高亮、不解释；但在卡片、occurrence 列表或总词库来源链接中点击时，仍可定位到原文并短暂闪烁。复杂新用法可轻微提示。
- **ignored**：永不主动显示，除非用户恢复。

### 5.1 产品语义：学习中、已掌握、删除（用户向）

本节用**用户可见概念**归纳语义；与底层 **`mastery_status`** 枚举的对应关系在括号中说明。**「忽略」**（`ignored`）仍为「不想继续学但保留记录」，**不等于**「删除」；删除语义见 **Phase 3.6** 及下节「删除」。

#### 学习中

- 含义：**有效学习项**；用户**尚未**声明已完全掌握。
- **保留**在个人词库/语法库（作为持续学习对象）。
- **以后**在新文章中再次出现同类表达时，**AI 仍可推荐**（与推荐策略一致）。
- 在**单篇文章页**右侧词汇/语法**主列表**中**默认展示**（与 **§5.3** 一致）。
- **数据对应**：尚未标记为 **`mastered`** 且非 **`ignored`** 的条目；通常对应 **`new` / `learning` / `familiar`** 等（界面文案可统一称「学习中」或保留档位细分，由实现决定）。

#### 已掌握

- 含义：**有效学习项**；用户声明**已经会了**。
- **保留**在词库/语法库，作为**学习记录**（非删除）。
- **以后** AI **默认少推荐或不主动推荐**（降低重复打扰）。
- 在**当前文章页**中可**默认折叠**，不占主要阅读空间；用户可**展开**查看已掌握项，也可**恢复为学习中**。
- **数据对应**：**`mastery_status = mastered`**。

#### 暂忽略

- 含义：用户**暂时不想学**该项；**不代表**已经掌握。
- **保留**在个人词库/语法库（记录仍在，**不是**删除）。
- **以后** AI **默认不主动推荐**该项（与推荐策略一致，见 **§13.5** 方向）。
- 在**单篇文章页**右侧：与「已掌握」类似，**默认折叠**到 **「暂忽略词汇/语法」** 区域（**Phase 3.7+** 实现细节见 **`DEVELOPMENT_LOG.md`**）；用户可**展开**查看，并可**恢复为学习中**。
- **若用户之后在文中再次手动添加**同类表达（或产品侧判定为同一学习意图）：可视为**重新需要学习**，宜将状态**恢复为学习中**（与具体合并/去重规则以代码为准；**不**将「暂忽略」等同于「已从总库删除」）。

#### 删除

- 含义：**误添加**、**重复项**、**识别错误**，或用户**完全不想保留**的**无效学习项**（从学习视角）。
- **从当前文章**的学习列表中**移除**；**不进入**以本篇为基础的复习流（若产品后续有复习功能）。
- **不表示**用户已经掌握（与「已掌握」明确区分）。
- **产品目标**：从用户视角，该项**不应再作为本篇学习项**出现；**总词库是否仍保留底层词条行**可随版本演进（**当前阶段**实现见 **`DEVELOPMENT_LOG.md`** **Phase 3.6**：仅从本文删除 **occurrence**，**`vocabulary_items` / `grammar_items` 行可保守保留**——与「主记录从总词库彻底消失」的最终形态可**分阶段收敛**，本 PRD 先固定**用户语义**与**文章侧体验**）。

### 5.2 未来用户手册（示例说明）

以下示例供**未来用户帮助 / FAQ**撰写时参考（非当前界面逐字稿）：

- 若该词/语法你还想继续学，请在状态下拉菜单中保持 **「学习中」**。
- 若你已经掌握了，请在状态下拉菜单中选择 **「已掌握」**。条目**仍会保存在词库/语法库**里作为记录，但以后 **AI 会尽量少推荐**。
- 若你**暂时不想学**（不代表已会），请在状态下拉菜单中选择 **「暂忽略」**。记录仍保留；**AI 默认不主动推荐**；可在折叠区通过同一下拉菜单**恢复为学习中**；若之后在文中**再次手动添加**，可视为重新需要学习。
- 若是误加、识别错或你**完全不想保留**的项目，请点 **「删除」**。**删除**不会表示你已经掌握；从**本篇**学习面板消失，且不当作本篇的复习对象。（总词库侧行为以当时版本说明为准。）

### 5.3 单篇文章页右侧学习面板：分组与显示规则（目标行为）

**已实现（Phase 3.7+，以代码为准）与原则对齐如下**：

- **默认优先展示「学习中」**的词汇与语法（主列表区域，占主要阅读空间）。
- **学习中 / 已掌握 / 暂忽略** 的修改入口使用轻量状态下拉菜单，避免在词汇/语法卡片中放置过多显眼操作按钮；**阅读项列表卡与详情卡**将下拉与 **「删除」** 一并放在**标题行右侧**（词汇详情旁为发音按钮），左侧标题区使用 **`min-w-0` + `break-words`**，长词在左栏换行，**不**与右侧操作抢同一行；右侧操作组 **`shrink-0` + `flex-nowrap`**，避免状态下拉与删除被挤成异常断行。无单独「状态」标签，适用 `aria-label`「学习状态」以兼顾无障碍。
- **「已掌握」**的词汇与语法**默认折叠**到 **「已掌握词汇/语法（n）」** 区域；用户可**展开**查看，并可通过状态下拉菜单**恢复为学习中**。
- **「暂忽略」**的词汇与语法**默认折叠**到 **「暂忽略词汇/语法」** 区域；用户可**展开**并通过状态下拉菜单**恢复为学习中**。
- **已删除**的项目**不显示**在本篇学习面板中（已从本篇 **occurrence** 移除；**不等于**已掌握，见 **§5.1「删除」**）。

## 6. 阅读页

### 桌面端

- 左侧：原文。
- 右侧 Tabs：**词汇**、**语法**、**摘要**、**阅读问题**。
- 原文中高亮重点词和语法结构。
- 点击高亮词 → 右侧显示词汇详情。
- 点击语法高亮 → 右侧显示语法解释。

#### 左右联动与布局（桌面）

- **右侧学习面板**：使用 **`sticky`**（如 **`top-20`**，避开顶栏）、**`max-height`** 接近视口（如 **`calc(100vh - 100px)`**），面板内 **Tabs 内容区可滚动**；**左侧文章卡片**单独 **`overflow-y-auto`**（约 **`max-h-[calc(100vh-100px)]`**），左右可**独立滚动**，互不代替对方滚动。
- **点击左侧词汇 / 语法高亮** → 自动切换到对应 **Tab**，右侧列表 **`scrollIntoView`**（如 **`block: "nearest"`、`behavior: "smooth"`**）定位到对应卡片；卡片附加短暂 **`ring`** 强调（约 **1–2 秒**），与当前**选中态**（边框 / 背景）可同时存在。
- **手动添加词汇 / 语法成功**（选区浮层或表单）→ 同上：切换 Tab、滚动到卡片、短暂强调。
- **右侧词汇 / 语法列表项或详情卡片 `hover`**（鼠标悬停）→ 左侧原文中该条目**全部 occurrence** 临时**加强高亮**（如 **`ring` / `outline`**，**不改变**系统/用户语义色）；鼠标离开后恢复普通高亮。**移动端**无精细 hover 时，点击列表卡片可短时触发同类左侧强调（约 **2 秒**）。
- **详情区「本篇出现位置」**：每条 occurrence **可点击** → 左侧文章区域 **`scrollIntoView`**（如 **`block: "center"`、`behavior: "smooth"`**）滚到对应片段；该处短暂 **`animate-pulse` + ring** 反馈。文中词汇高亮一般为 **`button`**，须具备 **`data-marker-id`、`data-occurrence-id`、`data-range-id`**（或等价）以便定位；**语法高亮**可为 **`span role="button"`**，同样携带上述 **data-** 属性。词汇与语法正文高亮均须允许 **`user-select: text`**，以便拖选**穿过**多个已有高亮，将整句（含内部已标词）加入词库；点按打开详情由各组件的 `click` / `pointerdown` 处理。
- **已掌握词汇**：正文默认不显示绿色 / 琥珀色常驻高亮，以减少阅读干扰；但保留原文锚点。用户从右侧已掌握词汇折叠区、词汇卡片 occurrence 或总词库来源链接点击时，仍应滚到原文并短暂显示定位 ring。已掌握词锚点优先级应低于仍需展示的语法或学习中高亮。
- **移动端触摸**：文中**词汇**与**语法**高亮均允许在片段内及**跨高亮**拖选子串，以使用选区浮层「加入词库」；**词汇**在触摸 **`pointerdown`** 上可 `preventDefault` 以优先保证点按打开词汇详情、减少误触系统菜单；**语法**触摸时不在 `pointerdown` 上 `preventDefault`，轻点（无选区）打开语法详情。语法区域可保留系统 touch callout 以利于选词。
- **本阶段不做**：根据左侧文章滚动位置**自动同步**右侧列表位置的复杂联动。

### 手机端

- 单栏阅读。
- 点击高亮词后，底部弹出解释卡片；移动端**词汇**与**语法**高亮均须允许拖选穿过已有高亮以加入词库；词汇在触摸 `pointerdown` 上可 `preventDefault` 以优先点按打开详情。**语法**在无选区时轻点打开语法说明。
- **底部详情抽屉**：全屏变暗层仅作视觉提示，须 **`pointer-events: none`**，不得拦截用户对课文卡片的滑动与选词；抽屉高度宜有上限（如约 **50dvh**），打开后应将对应文中高亮 **滚入抽屉上方的可视留白**，避免解释区挡住用户正在看的蓝 / 紫高亮。收起以抽屉内「关闭」为主（不要求点击变暗区必能关闭）。
- 底部 Tab：**词汇**、**语法**、**摘要**、**问题**。

## 7. 发音功能

- 所有高亮词支持发音。
- **默认不**在 hover 时自动播放。
- **点击**发音按钮播放；按钮点击处理须 **`preventDefault` + `stopPropagation`**，避免触发父级选中/切换逻辑。
- 使用浏览器 **Web Speech API**（`window.speechSynthesis`）。
- 实现要点（`speakGerman` / `PronunciationButton`）：
  - 每次播放前执行 **`speechSynthesis.cancel()`**，避免队列卡住或叠读。
  - 使用 **`SpeechSynthesisUtterance`**：`lang` 默认 **`de-DE`**，`rate = 0.9`，`pitch = 1`。
  - 若 **`getVoices()`** 中存在 **`lang` 以 `de` 开头** 的 voice，可选绑定（同档优先 `de-DE`）；**列表为空或未匹配到德语 voice 时仍必须调用 `speak`**，仅依赖 `utterance.lang`，不得因此跳过朗读。
  - **用户激活（user gesture）**：`speak` 须在用户 **click** 等手势的处理函数中 **同步** 调用。使用 **`setTimeout` / 仅等 `voiceschanged` 后再首次 `speak`** 可能导致 Chromium 等浏览器 **静默忽略** 合成（无声音、无报错）。
  - 空文本时不应调用 `speak`，并提示 **「没有可播放的文本」**（如控制台或页面反馈）。
  - `PronunciationButton` 点击时建议 **`console.log`** 便于确认事件已触发；可短时展示 **「正在播放：…」** 等页面反馈。
  - 开发调试可在控制台查看每次朗读的文本与所选 voice。
- 词汇详情、选区浮层、词库页等统一使用同一 **`PronunciationButton`**；设置页提供 **「测试德语发音」**（*Guten Tag*）及 **「直接测试 speechSynthesis」**（最小 API 调用）用于区分组件问题与系统/浏览器 TTS 问题。
- 浏览器不支持 `speechSynthesis` 时：页面提示 **「当前浏览器暂不支持发音」**（必要时可辅以 `alert`）。
- 后续可接高质量 TTS。

## 8. 用户手动补充词汇和语法

系统不能只依赖 AI 判断用户不懂什么。真实阅读中，AI 可能漏掉用户不认识的单词、短语或语法结构。因此阅读页必须支持 **AI 自动推荐 + 用户手动补充**。

### 8.0 原文高亮区分与优先级

- **用户手动添加的词汇和语法必须在原文中以不同颜色高亮**，与系统自动标出的课文词汇、课文语法**一眼可区分**（例如：课文词汇与课文语法各一套配色；**「用户」**徽标对应的词汇使用琥珀/黄色系；用户语法使用紫色系；具体色值由设计实现）。数据模型上仍使用 `source = ai_detected` 表示系统推荐；界面中文案可与「系统词汇 / 系统语法」对举，避免与「**用户** / 用户语法」混淆。
- 用户通过选区「加入词库」或「标记语法」保存后，对应字区间应**立即**在左侧原文中渲染为高亮，并在 hover tooltip 或详情中标注 **「用户」**、**「用户语法」** 等文案。
- **重叠规则**：若同一字区间既匹配 AI 词汇又被用户添加为词汇，**原文样式优先采用用户添加**；右侧详情区仍应**保留**课文词汇侧与用户侧可用的信息（避免用户丢失系统解释）。
- **词汇与语法重叠、已掌握词显示、选区与语法高亮内标词等（实现细则与将来用户手册素材）**：见 **[`docs/READING_HIGHLIGHTS_AND_OVERLAPS.md`](./READING_HIGHLIGHTS_AND_OVERLAPS.md)**。
- 通过右侧表单「手动添加」、且无法在文中定位偏移的条目，可仅在列表中展示；**有选区偏移时必须在原文中高亮**（接入持久化与 `start_offset`/`end_offset` 后统一约束）。
- **定位可靠性**：用户手动添加项目的高亮必须**严格对应用户选中的文本**（`selectedText` / `surface_form` 与原文 substring 一致）。若以 DOM Range 计算的 `start_offset` / `end_offset` 映射到当前 `articlePlain` 后**与选中文本不一致**，则视为不可靠，必须 **fallback 到在 `articlePlain` 上对 `selectedText` 的精确匹配**（多处重复时取距 DOM 估算位置最近的一处）。禁止出现「列表显示 A 词、原文却高亮 B 词」的错位。

### 8.1 选区浮层（原文中选中）

用户可在原文中选中任意单词或短语（或句子），系统显示小浮层，包含：

- **加入词库**
- **标记语法**
- **发音**

#### 点击「加入词库」后

- 将选中文本加入**当前文章**词汇列表。
- `source = user_added`
- `mastery_status = new`
- `zh_meaning = 待 AI 补充`
- `simple_de_explanation = Wird später ergänzt.`
- 右侧**词汇** Tab 立即显示新词。
- 后续接入 AI 后补全：`lemma`、词性、中文解释、简单德语解释、例句和上下文含义等。

#### 点击「标记语法」后

- 将选中文本加入**当前文章**语法列表。
- `grammar_key = user_question`
- `name_zh = 用户标记的语法问题`
- `explanation_zh = 待 AI 分析`
- `mastery_status = new`
- `source = user_added`（语法条目侧；实现时与数据模型对齐）
- 右侧**语法** Tab 立即显示新项目。
- 后续由 AI 判断是否映射到固定分类（如 `relative_clause`、`passive_werden`、`konjunktiv_ii` 等）。

### 8.1.1 长文本选区与「添加为词汇」的设计原则（Lexical item 广义）

用户在阅读德语文章时，可能选中**一段看起来像句子或较长短语**的文本，再点击 **「加入词库」/「添加为词汇」**。这**不**应被简单理解为「把整句话当作一个普通单词保存」，而应理解为：用户认为该片段属于**词汇/表达层面（lexical / phraseological）**的学习需求，**而非**语法结构分析层面。与点击 **「标记语法」** 的意图明确区分。

**示例（可分动词）**：原文含 `brachte … seine Frau um` 等片段；用户选中较长范围并点 **「加入词库」** 时，系统与后续 AI 应**优先**按**可分动词**（如 **`umbringen`**）等**词汇型表达**理解，而不是只当作普通动词 **`bringen`**，也**不应**在用户未点「标记语法」时默认归为整句语法问题。

#### 「添加为词汇」——词汇 = 广义的 lexical item

- **单个词**：大概率按**普通单词**学习与展示。
- **多个连续词**：视为**词汇型表达候选**，可能包括：**短语**、**搭配**、**固定表达**、**可分动词**、**介词搭配**、**动词搭配**、**新闻常用表达**等。
- **选区较长仍点「添加为词汇」**：
  - **尊重用户意图**，先按**词汇型表达**路径处理；
  - **AI** 可进一步判断 **subtype**（见下）；
  - **不要**简单等同于「把整句当普通句子条目」存完即了事；
  - **不要**在用户明确点的是「词汇」时**直接**当作语法结构题处理（除非用户改选 **「标记语法」**）。

#### 「添加为语法」——仅当用户点击「标记语法」

此时才按**语法结构**理解与后续分析，例如：**从句**、**被动**、**不定式结构**、**关系从句**、**Konjunktiv**、**长句结构**、**介词结构**等（与 §8.1 既有方向一致）。

#### AI 主动推荐（全文分析）亦应识别表达型词汇

**未来**真实 AI **分析整篇文章**时，**不应**只推荐**单个生词**，也应主动识别对用户理解有帮助的**表达型词汇**（与手动「加入词库」同属**广义 lexical item**，见上节）。推荐范围宜覆盖（示例）：

1. **单个单词**：如 `Täter`
2. **复合名词**：如 `Untersuchungshaft`、`Kriminalstatistik`
3. **短语 / 搭配**：如 `in fünf Fällen`
4. **固定表达**：如 `in Kauf nehmen`
5. **介词搭配**：如 `auf etwas angewiesen sein`
6. **动词搭配**：如 `eine Entscheidung treffen`
7. **可分动词**：如原文 `brachte … um` → **`umbringen`**；`richtet … ein` → **`einrichten`**
8. **新闻常用表达**：如 **`unter Druck geraten`**、`eine Entwicklung zeichnet sich ab`

**与用户选区一致的示意**（亦见上表）：**`Täter`**；**`in fünf Fällen`**；**`unter Druck geraten`**；**`eine Entscheidung treffen`**；可分动词拆分形式与词典形对照等。

**设计原则（主动推荐的目标）**

AI 主动推荐的目标**不是**列出文中所有单词，而是找出：

- 按用户**当前 CEFR** 水平**可能阻碍理解**的词汇与表达；
- 用户**自己不一定知道该如何划选**的表达；
- 对理解**文章主旨与关键细节**有帮助的表达；
- **新闻阅读**中**高频、有复用价值**的表达。

这些表达型条目可先**统一进入「词汇」Tab**，**不必**为表达型单开新 Tab。UI 演进上可展示 **`item_type` 标签**（面向用户的文案示例）：**单词**、**短语**、**搭配**、**可分动词**、**固定表达**、**复合名词**等（与枚举值映射由实现定义）。

#### 用户选区触发的 AI 辅析（「加入词库」）

当用户选中**较长文本**并点击 **「添加为词汇」** 时，AI 宜尝试识别是否涉及例如：**可分动词**、**固定搭配**、**介词搭配**、**动词短语**、**惯用表达**、**新闻常用表达**等（与上表同类）。

#### 数据与 API 预留字段（规范级，非当前实现承诺）

**PRD**、**未来 prompt** 与 **schema** 设计宜预留（与当前库表无强制对齐）：

- **`item_type`**（或 **`expression_type`** / 同类枚举）：如 `single_word`、`phrase`、`collocation`、`fixed_expression`、`separable_verb`、`compound_noun`、`news_idiom` 等；
- **`surface_form`**：原文表面形式；
- **`canonical_form` / `lemma`**：规范形式（如可分动词的词典形）；
- **`occurrence_sentence`**（或等价）：该表达所在句 / 上下文句，便于复习与验收；
- **中文解释**、**简单德语解释**（或 **`explanation`** 结构化子字段）；
- **用户选区路径**下还可有：**为何判为词汇型表达而非语法点**（简短理由）。

#### 可分动词示例（产品期望）

**用户选区**：原文片段含 `brachte … seine Frau um`；用户选中较长范围 → **「加入词库」**。期望识别方向（示例）：`item_type = separable_verb`，`lemma = umbringen`，`surface_form` 可概括如 `brachte … um`，释义与解释中说明：**可分动词**、过去式中词干与可分前缀位置等。

**AI 主动推荐**：若原文含 `brachte 2025 ein Schweizer … seine Frau um`，AI 应能**主动**推荐该表达型条目，例如：`item_type: separable_verb`，`lemma: umbringen`，`surface_form: brachte … um`，中文解释：杀害 / 使……丧命，简单德语解释，并说明：这是可分动词，`um` 在句尾，动词核心为 `brachte`。

#### 第一版（当前）简化原则

- **UI** 仍可**只保留**选区两个入口：**添加为词汇**、**添加为语法**（不必强制用户再选「短语 / 搭配 / 可分动词」等子类型）；**AI 推荐结果**仍先**统一归入 vocabulary 条目**展示在**词汇** Tab，**无需**第一版就拆复杂表结构。
- **内部文档**与**未来 schema / prompt** 应预留 **`item_type`**、**`surface_form`**、**`canonical_form` / `lemma`**、**`occurrence_sentence`**、**`explanation`**（及与 **`expression_type`** 的等价命名空间），以便在不大改 Tab 结构的前提下演进 AI 输出与存储。

### 11.2 occurrences 与 senses 的长期设计

- **items（vocabulary_items / grammar_items）**：跨文章的学习实体，承载掌握度与稳定元数据；**同一词条或语法项只有一条主 item**，通过 **`last_seen_at`、occurrence 记录** 反映跨文章复现。
- **occurrences**：删除文章时应移除该 **`article_id`** 下的全部 occurrence（与长期 **items** 主记录分离，见 **§12.8**）；支撑原文高亮、复习跳转与统计；每条 occurrence 的 **`created_at`** 表示**该词 / 该语法点在该篇文章中的这一次出现**的记录时间（见 **§12.4**）。
- **senses**：把「一词多义」从单条释义中拆出；**occurrence** 可选指向 **sense**，便于同一词在不同文章语境下挂不同义项。

### 11.3 RLS

- 所有上表 **启用 RLS**。
- **profiles**：仅 **`id = auth.uid()`**。
- **其余表**：**`user_id = auth.uid()`** 下的 SELECT / INSERT / UPDATE / DELETE（含 `WITH CHECK`）。

### 11.4 自动化

- **profiles、articles、vocabulary_items、vocabulary_senses、grammar_items** 在 UPDATE 时由触发器维护 **updated_at**。
- 未来新增 **`finished_at` / `mastered_at` / `ignored_at`** 等列时，由应用层在状态变更时写入；是否补充触发器可按迁移脚本统一约定。

## 12. 时间字段与学习进度设计

本节约定**文章、词汇、语法、出现记录**的时间语义与**学习价值**，与 [`docs/DATABASE.md`](./DATABASE.md) 一致。**当前阶段**以文档与设计为主：**已有 schema 字段继续沿用**，**不强制**立即执行 DDL 增加下列「后续列」。

### 12.1 文章（articles）

| 字段 | 含义 |
|------|------|
| **created_at** | 用户**保存 / 导入**文章的时间（入库时间）。 |
| **updated_at** | 文章记录**最后修改**时间（如标题、正文、摘要等更新）。 |
| **finished_at** | 用户**标记读完**文章的时间；**后续阶段**添加。 |
| **read_status** | 文章**阅读状态**；**后续阶段**添加。 |

**read_status** 可选值（约定）：

- **saved**：已保存，尚未进入稳定阅读流程（或默认态，具体与产品流程对齐）。
- **reading**：正在读。
- **finished**：已读完（可与 **finished_at** 联动）。
- **archived**：归档（仍保留数据，列表与推荐策略可降权）。

### 12.2 词汇（vocabulary_items）

| 字段 | 含义 |
|------|------|
| **created_at** | 该词条**第一次进入总词库**的时间。 |
| **updated_at** | 词条元数据**最后修改**时间。 |
| **last_seen_at** | **最近一次**在某一篇文章中**遇到**该词的时间（应用层在写入 / 汇总 occurrence 时更新）。 |
| **mastered_at** | 用户将掌握状态标为 **mastered** 的时间；**后续阶段**添加。 |
| **ignored_at** | 用户将状态标为 **ignored** 的时间；**后续阶段**添加。 |

### 12.3 语法（grammar_items）

| 字段 | 含义 |
|------|------|
| **created_at** | 该语法项**第一次进入总语法库**的时间。 |
| **updated_at** | 语法项**最后修改**时间。 |
| **last_seen_at** | **最近一次**在文章中遇到该语法的时间。 |
| **mastered_at** | 标为 **mastered** 的时间；**后续阶段**添加。 |
| **ignored_at** | 标为 **ignored** 的时间；**后续阶段**添加。 |

### 12.4 出现记录（vocabulary_occurrences / grammar_occurrences）

- **`created_at`**：该词汇或语法在**某篇文章中的这一次出现**被写入数据库的时间（出现记录时间）。
- **数据模型**：同一 **vocabulary_item** 或 **grammar_item** 仅一条**主 item**；可对应**多条** occurrences（不同文章、不同位置、不同时刻）。

### 12.5 总词库「今日词汇记录」：新增生词与再次遇到（产品规则）

**目标**：在**总库不重复**（同一 `(user_id, normalized_key, part_of_speech)` 一条 **`vocabulary_items` 主词条**）的前提下，让用户在「今日」维度既能看到**今天第一次进入总库的词**，也能看到**以往已在库中、但今天在新文章（或新保存流程）中又出现了的词**，且**新增数与复现数分开统计**，避免虚高或遗漏。

#### 「今日」的自然日与归属时间

- **自然日**：按用户**本地时区**的日历日界定（界面筛选与文案以此为准；库内为 **`timestamptz`**，客户端换算）。
- **归属**：以 **`vocabulary_occurrences.created_at`**（或保存事务中写入该条 occurrence 的等价时间戳）判定某次出现是否落在「今日」。与 **`vocabulary_items.created_at`**（主词条首次入库时间）**分工不同**，不可混用为同一统计口径。

#### NEW（新增 / 今日新增生词）

- **语义**：仅当 **`vocabulary_items` 行在某自然日首次被创建**时，该主词条在该日记为 **新增**，列表标签 **NEW / 新增**。
- **计数**：「今日新增生词」**只统计**当日**新创建的主词条**条数；同一词同一天内仅因合并写入产生**一行** item 时，**只计 1 次**。
- **同一天多篇文章**：先在文章 A 保存 → **创建主词条** → **NEW**。后在文章 B 再保存同一键 → **不创建新 item**，**不计入**「今日新增生词」。
- **并发首次保存**：须合并为**一条** `vocabulary_items`（应用层按唯一键 upsert），**只计 1 次 NEW**。

#### REPEAT（再次遇到 / 今日再次遇到）

- **语义**：主词条**已存在**时，当日保存流程中**仅新增** **`vocabulary_occurrences`**（新文章或同文新位置，以实际写入为准）→ **再次遇到**，列表标签 **REPEAT / 再遇到**。
- **列表与跳转**：须出现在「今日词汇记录」类视图中，附带**本次来源文章**；可跳转 **`/articles/[id]`** 并**定位到对应 occurrence / 单词卡片**（与阅读页一致）。
- **总词库展示**：该主词条下**来源文章列表仍累积**今日这篇文章（与其它 occurrence 一并展示）。

#### 词性、搜索与统计口径

- **词性不一致**：`noun` 与 `phrase` 等为**两条主词条**（唯一键含 **`part_of_speech`**）。**NEW / REPEAT 分别归属对应主词条**，各自统计。
- **学习统计**：以 **`vocabulary_item`（主词条）** 为主维度汇总；**occurrence** 支撑「再次遇到」、次数与原文定位。
- **搜索（规划）**：可按 **surface form** 聚合呈现多条主词条或 occurrence；**存储层**仍以主词条 + occurrence 为稳定结构。

#### 与既有规则的一句话条文

若词汇**已存在于总库**，再次在今日文章保存时：**不**创建新主词条，**不**计入「今日新增生词」；**应**计入「今日再次遇到」，并在今日词汇记录中展示，附带本次来源文章，且可定位回原文。

#### 语法库

- **原则对齐**：**`grammar_items` / `grammar_occurrences`** 采用与词汇**相同的 NEW / REPEAT 语义**（主 item 当日首次创建 vs 当日新 occurrence），避免两套日历逻辑。

#### 实现状态

- **`/vocabulary`**：**「今日词汇记录」** Tab 已实现本节 **NEW（新增）** / **REPEAT（再遇）** 筛选与列表标签（本地自然日、`vocabulary_items.created_at` 与 **`vocabulary_occurrences.created_at`**）；其余时间 Tab（昨日 / 近三日 / 本周）逻辑未改为本节口径（仍以 **`vocabulary_items.created_at`** 为主，与历史一致）。详见 **`DEVELOPMENT_LOG.md`**。

### 12.6 学习价值（产品侧）

上述时间字段与状态共同支撑：

- **本周新增词汇**（实现进阶后：「新增」与「再次遇到」见 **§12.5**；此前可按 **created_at** / occurrence 粗聚合）。
- **本月高频语法**（如按 occurrence **`created_at`** 与 **grammar_item_id** 统计）。
- **最近反复出现但未掌握**的词汇（occurrence 频繁 + **`mastery_status` ≠ mastered**）。
- **已掌握**内容默认**不再主动解释**（结合 **mastered** 与未来的 **mastered_at**）。
- **ignored** 内容**不再主动显示**（结合 **ignored** 与未来的 **ignored_at**）。
- 根据用户**真实阅读历史**与掌握情况，**调整下一篇文章的解释强度**（与 **profiles** 水平字段、 occurrence 统计等联动）。

### 12.7 数据库演进建议

- **当前**：在应用与文档中**对齐已有列**（如 **articles / items** 的 **created_at、updated_at、last_seen_at**）；**read_status、finished_at、mastered_at、ignored_at** 可先由产品逻辑预留，**不必立刻改 schema**。
- **后续迁移可新增**（示例）：
  - **`articles.read_status`**（`text` 或枚举）
  - **`articles.finished_at`**（`timestamptz`，可空）
  - **`vocabulary_items.mastered_at`**、**`vocabulary_items.ignored_at`**
  - **`grammar_items.mastered_at`**、**`grammar_items.ignored_at`**

### 12.8 删除文章（未来产品规则）

用户将来应能删除此前**导入/保存**的文章。设计须区分两类数据：**文章级数据**（随文章存亡）与**长期词库/语法库主记录**（跨文章的学习实体）。

#### 删除文章时应删除的内容（与该 `article_id` 强绑定）

- **`articles` 记录**：含正文、标题、来源、URL、发布时间等凡存于该行的元数据（本产品设计下部分元信息亦可能嵌入 **`original_text` 前部**，删除文章即一并消失）。
- **文章级 AI 字段**：**`summary_zh`**、**`summary_de_simple`**、**`reading_questions`**。
- **该文章中的词汇出现**：**`vocabulary_occurrences`** 中 **`article_id = 该篇`** 的全部行。
- **该文章中的语法出现**：**`grammar_occurrences`** 中 **`article_id = 该篇`** 的全部行。
- **阅读体验层面**：左侧原文高亮、右侧学习面板中的「本篇出现位置」均依赖 occurrence；删除文章后，该篇不再有任何高亮或本文定位。

**用户可见结果**：该文章从 **dashboard / 文章列表**中消失；**无法再打开** **`/articles/[id]`** 阅读页（链接失效或提示不存在）。

#### 删除文章时不应默认删除的内容（长期学习库主记录）

- **`vocabulary_items`**
- **`vocabulary_senses`**
- **`grammar_items`**

**原因**：同一词汇项或语法项可能出现在**多篇文章**中；删除其中一篇**不应**误删用户在长期词库/语法库中的学习记录与掌握状态。

#### 推荐第一版实现策略

第一版删除文章时：

1. **删除** **`articles`** 中对应行（或等价地使该用户对该篇记录不可见且数据移除，以实现列表与阅读页不可用）。
2. **删除** 该 **`article_id`** 下的全部 **`vocabulary_occurrences`**、**`grammar_occurrences`**。
3. **不删除** **`vocabulary_items` / `vocabulary_senses` / `grammar_items`**。

若某词条或语法点**仅在该篇文章中出现过**，第一版仍**保守保留**其主记录，避免误删学习历史；后续可通过单独「清理」能力处理孤儿条目（见下节）。

#### 后续可选能力（不在第一版）

- **清理无来源/无 occurrence 的词条**（或孤立主记录），由用户主动触发或在设置中提供。
- 删除文章时**可选**：是否同时删除「仅属于该文章」的 **`vocabulary_items` / `grammar_items`**（需清晰定义「仅属于」与确认层级）。
- **归档文章**（例如 **`read_status = archived`**）代替永久删除，列表降权但仍可恢复。

以上均为产品演进选项，**第一版以实现「删文章 + 删 occurrence + 保留 items/senses」为基准**。

#### 删除确认文案建议

向用户展示确认时，建议使用：

> 确定删除这篇文章吗？这会删除文章正文、摘要、阅读问题，以及本文中的高亮和出现位置。已经保存到词库/语法库的长期学习记录不会自动删除。

**说明**：本节为**产品规则**；具体 API、RLS、`ON DELETE` 级联或应用层删除顺序以实现约束，由实现阶段设计与评审，**不要求在本阶段修改 schema**。

## 13. AI 词汇与语法推荐原则（Phase 3.1 起真实 OpenAI）

本节描述**真实 AI 分析**（相对 Phase 3.0 **Mock**）的产品意图与水平逻辑。**Phase 3.0** 仅验证 UI 与数据流，**不以此评估最终推荐质量**。**Phase 3.1+** 已用 **OpenAI 结构化输出** 生成与 **`ArticleAnalysisResult`** 同结构的分析；阅读页**预览**后，用户可先删除不需要的 AI 候选、标记学习状态，再 **Phase 3.2「确认保存」** 写入 **`vocabulary_*` / `grammar_*`**，**Phase 3.4** 同时写入 **`articles`** 摘要与阅读问题（见 **§1.4.1**）。

### 13.1 AI 推荐的核心目标

AI 自动分析的目标**不是**罗列文中所有生词，而是：

用户在**开始通读全文前**，先浏览系统标出的**关键词汇与语法点**；结合释义后，应能**大致把握文章主旨与关键细节**，通读过程中**不必频繁停下去查词**。

据此约定原则：

- **优先**推荐**阻碍理解主旨与关键细节**的词汇与语法（含结构、搭配、语块）。
- **不追求**解释每一个可能生词。
- **不推荐**明显**人名、地名、媒体名、公司名**等专名，**除非**该专名本身具有**语言学习价值**（如构成固定表达、文化负载词等）。
- **推荐数量可控**，避免高亮过满、干扰阅读；**上限与「非凑数」规则**见 **§13.6**。

**表达型词汇**：AI 推荐的「词汇」宜包含**单词、复合词、短语、搭配、固定表达、可分动词、新闻常用表达**等广义 lexical item，**不单限于单词**；与 **§8.1.1**（用户选区与 AI 主动推荐的产品语义、**`item_type`** 预留）对齐。

### 13.2 CEFR 与用户选择水平

产品支持用户**手动选择** CEFR 档位作为阅读辅助强度（见 **§4**；导入/分析时可写入 **`articles.user_level_at_analysis`** 等）。**A2、B1、B2** 为新闻阅读场景的重点区间；**C1** 可预留。**默认重心**可放在 **A2–B2**，尤其 **B1/B2**（能坚持新闻学习的用户通常接近或达到 **B1**）。

**当前阶段**已实现：

- 用户**手动选择**水平；
- AI **依据该选择**调整推荐侧重点与数量（见 **§13.3、§13.6**）；
- **服务端**生成结构化分析；阅读页**预览**；用户可在预览区删除候选或改状态，**显式保存**后写入 **`vocabulary_*` / `grammar_*`** 与 **`articles`** 相关字段（**不**在刷新或打开文章时**自动**重复调用 AI，见 **Phase 3.14**）。

**暂不实现**（留待更后阶段）：

- **自动 CEFR 测评**、完整**词汇量估算**；
- **自适应水平自动切换**、长期**学习模型**与复杂个性化；
- 仅可在文档中预留 **§13.5** 所述**动态反馈**方向。

### 13.3 按水平的推荐侧重（指导 AI 提示与验收）

以下为**产品侧期望**，供 Phase 3.1+ 提示工程与验收参考，**非硬性枚举词表**。

**A2**

- 更多**基础词汇**、**常见动词/名词**、**高频介词短语**
- **简单从句**、**基础时态与句型**

**B1**

- **新闻常见词**、**可分动词**、**复合名词**、**固定搭配**、**抽象名词**
- **常见从句**、**被动语态**、**影响理解的长句结构**

**B2**

- **减少**基础词占比
- **抽象表达**、**长复合词**、**隐含逻辑**、**语气与评价性表达**
- **复杂从句**、**Konjunktiv**、**间接引语（indirect speech）**
- 更细的**搭配**与**语体**差异

### 13.4 词汇等级来源与 `level_estimate` 表述

- **CEFR** 是**能力框架**，**不是**全球统一的单一「官方词表」。
- **德语**可参考：歌德 **A1/A2/B1** 词表、**Profile deutsch**、频率词表等（多源对照，产品不绑定唯一来源）。
- **英语**可参考 **English Vocabulary Profile（EVP）** 等（多语言扩展时）。
- 库字段 **`level_estimate`** 表示系统**估计**该词/语法点**适合**哪一 CEFR 阶段辅助学习，**不声称**经某一官方词表**绝对认证**。

### 13.5 动态水平反馈（未来功能，非 Phase 3.1）

以下行为**部分已落地**、部分后续可结合 **profiles**、手动添加、**掌握/忽略** 与 occurrence 统计实现：

- **整文词汇推荐与总词库（已实现）**：服务端 **`POST /api/analyze-article`** 在**已登录**请求下读取当前用户 **`vocabulary_items`** 中 **`mastery_status` 为已掌握或暂忽略** 的 **`normalized_key` + `part_of_speech`**，向模型说明并在返回结果上对 **`vocabulary`** 做**后处理剔除**（与库内唯一键对齐）。**学习中**（含 `new` / `learning` / `familiar`）或未出现在该集合中的词条不受影响；用户将词条**改回学习中**后不再命中剔除。**整文语法 `grammar` 与总语法库（已实现）**：读取 **`grammar_items`** 中已掌握/暂忽略的 **`grammar_key` + `normalized_key`**，向模型说明并对 **`grammar`** **后处理剔除**（与库唯一键对齐）；用户改回学习中后不再命中剔除。
- 用户自选 **B1**，但**频繁手动添加**明显 **A2** 高频词 → 可提示：是否更适合 **A2–B1 过渡**分析。
- 用户自选 **A2**，但常**忽略** A2/B1 推荐、且**已掌握**较多 B1 内容 → 可提示：可尝试 **B1** 分析。
- 用户**始终可手动**改回水平；**已忽略/已掌握**的词条，除上述整文词汇过滤外，其它动态提示仍以本节「后续」为方向。

### 13.6 AI 推荐数量与类型（非凑数原则）

本节固定**产品侧**对全文 AI 推荐数量与类型的约定，供提示工程与验收对齐。

- **词汇 / 表达**（广义 lexical item）：**不设固定条数上限**（2026-05-15 起临时调整）；应覆盖文中影响读懂、且符合 **userLevel** 的值得学项；**禁止**为凑数塞入过于简单、帮助很小的项目。
- **语法点**：**不设固定条数上限**（2026-05-17 起与词汇一致）；准确性优先，禁止为凑条数编造；篇幅短或较易的文章可自然较少。
- **正文送入模型**：单次整文分析默认仅使用正文**前 10 000 字符**（控制 token/费用/延迟与超长 JSON 失败率）；超长文响应带 warning，**后续**可做分块分析。
- **「词汇 / 表达」**包括（与 **§8.1.1**、**§13.1** 一致）：**单词**、**短语**、**搭配**、**固定表达**、**可分动词**、**复合名词**、**动词短语**、**介词短语**、**新闻常用表达**；**part_of_speech** 须按真实类型标注（动词/搭配/可分动词不得为凑冠词一律标成名词）。
- **核心目标**（与 **§13.1** 一致）：用户浏览推荐及释义后，应能**大致读懂文章主旨与关键细节**。
- **当前阶段不做**：**「显示更多词汇 / 展开更多推荐」**等能力；若 AI 漏项，用户**手动添加**后，可**补充 AI 解释**或使用阅读页 **「外部深入解释」**（外链，不产生本应用 API 成本）。
- **实现侧**：**`POST /api/analyze-article`** **单次** OpenAI 调用（**`SYSTEM_PROMPT`** in **`openaiArticleAnalysis.ts`**，含 Grammar v2 + 2026-05-15 词汇/冠词/词性指引）；**`json_schema`** 对 **`vocabulary`** / **`grammar`** 均**无** **`maxItems`**；规范化**不**截断条数。
