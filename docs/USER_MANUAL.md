# German Reading Coach — 用户说明手册（素材稿）

本文档用于**累积**将来对外「用户说明手册」可用的文案与结构，**不等于**已上架的帮助中心页面。正式手册可在适当时机由维护者与自动化助手根据本文档 + 产品界面 + **`docs/PRD.md`** 整理成独立版本（网页 / PDF / 长文等）。

**权威与差异**：产品目标与长期规则以 **`docs/PRD.md`** 为准；本文在「当前实现」处会注明与 PRD 中**尚未落地**或**部分落地**的差异，避免读者以为已全部自动化。

## 1. 导入文章（`/import`）—「正文」与「来源稿」

### 1.1 「正文」是什么

- **正文**是保存到云端后，在阅读页用来学习、划线、标词、跑 AI 分析的**定稿**。
- 链接抓取或「从剪贴板读取」后，系统会做**清理与排版**（例如去掉多余广告区、合并段落等），整理结果出现在正文编辑区。
- 点**保存文章**时，写入数据库的是**当前正文里的文字**（与阅读页一致）。
- **发布时间**（如 *Publiziert:* 行）在导入时可能出现在「可选信息」预览框，**不会自动写入正文**，也不参与整文 AI 分析；已保存旧文章若正文里仍有该行，可手动删掉。

### 1.2 「来源稿（可选）」是什么、何时出现

- **来源稿**里是**抓取或剪贴板刚读入时的原始文本**（粗稿），用来与**正文**同屏**对照**：是否删多了、段落是否错位、是否要手改后再保存。
- 为**可折叠**区块；**仅在有来源稿内容时显示**（尚未抓取或未读剪贴板时不会出现整块，不是界面丢失）。
- 与正文**一致**时可忽略来源稿；**不一致**时标题旁会提示常见原因（抓取/整理后差异多为正常），以您在正文中的编辑为准。

### 1.3 保存后与报社网页核对

- 学习与高亮均绑在**已定稿正文**上。
- 需与报社网站核对时，请用保存时填写的**文章链接**（若有）在浏览器打开原站。
- **当前**：来源稿**不**作为第二份长期字段写入数据库；长期对照以**正文 + 外链**为主。

### 1.4 导入方式概要

- **链接导入（默认）**：服务端抓取网页，填入标题与正文等；失败时可改**手动粘贴**或自行复制后使用「从剪贴板读取」。
- **手动粘贴**：可直接在正文区编辑；剪贴板按钮可将网页全文读入并走解析流程。
- **Chrome 插件**：从浏览器打开的文章预填到 `/import` 草稿（不绕过付费墙或登录墙）。

## 4. 阅读水平（CEFR）—「本篇」与「默认」

### 4.1 两个层次

- **设置页默认阅读水平**：账户常用水平；导入新文时可自动带入。
- **本篇阅读水平**（导入页或文章侧）：仅影响**当前这篇文章**分析时使用的水平（存入 **`articles.user_level_at_analysis`** 一类字段，以实际列名为准）。

### 4.2 等级含义（产品侧摘要，与 PRD §2 表一致）

| 等级 | 用户画像与系统行为（摘要） |
|------|---------------------------|
| **A1** | 入门；普通新闻往往偏难，解释更偏基础拆解。 |
| **A2** | 初级；可接触简化材料；仍多解释基础与中频结构。 |
| **B1** | 中级；**适合开始读真实新闻**；少解释过于基础的词，侧重新闻高频词、搭配、从句、被动等。 |
| **B2** | 中高级；减少基础词，侧重抽象表达、长句、语体、复杂结构等。 |
| **C1** | 高级；语气、风格、隐含意义等。 |
| **C2** | 精通向；MVP 中非核心。 |

### 4.3 重要说明

- **CEFR 是能力框架**，不是单一「官方词表」；界面中的 **`level_estimate`** 等是系统**估计**某词适合哪一阶段辅助学习，**不声称**经某一官方词表认证（见 PRD **§13.4**）。
- **本篇所选水平**主要调节：**整文 AI 分析**时推荐什么难度/类型的词与语法（见 **`openaiArticleAnalysis` 中 `userLevel` 指引**）、以及部分 **AI 补充解释**调用时的学习者水平；**不等于**您在全球德语考试中的正式等级证书。

## 5. 文中高亮、重叠与「先词后语法」等组合

实现细则见 **`docs/READING_HIGHLIGHTS_AND_OVERLAPS.md`**；此处给用户看的摘要如下。

### 5.1 同一位置只有一种颜色

正文按**字符**合并高亮：同一小段字**不会**叠两种颜色。重叠时按**优先级**决定显示哪一种（用户词汇/表达优先于用户语法，用户侧优先于 AI 侧等；已掌握词锚点默认最弱）。

### 5.2 先标单词，再在同一区域标语法，可以吗？

**可以。**词汇标注与语法标注**可以同时存在**；**重叠的那几个字符**会以**更高优先级**的类型显示（通常**词汇**优先于**语法**）。句子其余部分仍可显示语法色。

### 5.3 先标语法，再在语法片段里标生词，可以吗？

**可以。**在**蓝色/紫色语法高亮**内可用鼠标拖选子串，通过选区浮层**加入词库**（语法块使用可选中文本样式，便于拖选）。若当前有**非空选区**，轻点语法片段**不会**打开语法详情，以免误触。

### 5.4 词汇高亮上拖选整句（含句内已标词）

词汇高亮（绿/琥珀）支持 **`user-select: text`**，以便拖选**穿过**多个已有词汇高亮，把**整句表达**加入词库；与语法块策略对齐，细节见 **`READING_HIGHLIGHTS_AND_OVERLAPS.md`**。

### 5.5 已掌握词在正文中的显示

- **默认**：已掌握词**不常驻**绿/琥珀背景，减少干扰。
- **按需**：从右侧已掌握折叠区、本篇出现位置或总词库来源链接进入时，仍可滚到原文并**短暂闪烁**定位。

## 6. 选区与手动添加：词汇 vs 语法

### 6.1 通用步骤

1. 在正文中用鼠标拖选一段文字（尽量准确包含您要学的片段）。
2. 选区附近出现浮层：**加入词库** / **添加为语法**（具体文案以界面为准）。
3. **加入词库**：适合**词汇型表达**（单词、短语、搭配、可分动词句型等，见 PRD **§8.1.1**）。
4. **添加为语法**：适合**结构型难点**（从句、语序、被动态等）；与词汇分工见 PRD **§8.1.1**。

### 6.2 保存与云端

- 登录且数据库权限正常时，手动项会写入 **`vocabulary_*` / `grammar_*`**（详见 **`docs/DATABASE.md`**）。
- 若缺少义项等字段的迁移脚本，界面会提示在 Supabase 执行对应 **fix SQL**。

## 7. 整文 AI 分析（真实 OpenAI）— 怎么用

### 7.1 典型流程

1. 在阅读页点击**整文分析**（主按钮文案以界面为准），等待服务端返回（可能较慢，属正常）。
2. 在**预览区**查看推荐的词汇列表、语法列表、摘要与阅读问题。
3. **保存前可编辑**：删除不需要的候选条；将单条候选标为**学习中 / 已掌握 / 暂忽略**（以界面为准）。
4. **一键保存**：仅将**保留的候选**按所选状态写入数据库；摘要与阅读问题写入 **`articles`** 对应字段（须已执行 **007** 迁移，见 **`docs/DATABASE.md`**）。

### 7.2 数量与质量原则（产品约定，PRD §13.6）

- 词汇类推荐**不设固定条数上限**（由模型按文章与水平列举值得学项）；语法**上限 8 条**，阅读问题**3 条**；**禁止为凑数**塞无帮助项。超长正文（约一万字以上）目前只分析前半段，界面可能有提示。
- 推荐覆盖**广义词汇/表达**（短语、可分动词、复合名词等），不只单词。

### 7.3 词汇与语法分工（给用户的简单记法）

- **主要是「这个词/短语什么意思」** → 倾向 **词汇** Tab。
- **主要是「句子结构为什么这样组织」** → 倾向 **语法** Tab。
- 模型会尽量**同一位置不重复堆砌**；若预览里觉得分错了，保存前可删改或仅保存一侧。

## 8. 掌握状态与「总词库」— 用户可见规则

以下与 PRD **§5** 对齐；界面文案可能将 `new` / `learning` / `familiar` 等统一显示为**学习中**，以实际 UI 为准。

### 8.1 学习中（及未标为已掌握、非暂忽略）

- **含义**：您还在学的有效项。
- **本篇**：默认出现在主列表区域。
- **总库**：保留在 **`/vocabulary`**、**`/grammar`**，可继续改状态、看来源文章等。
- **产品规则**：在**以后的新文章**里，若 AI 仍认为该表达值得学，**仍可能再次推荐**（您可在新文章的预览里再次删除或改状态）。

### 8.2 已掌握

- **含义**：您声明**已经会了**。
- **本篇**：可默认折叠在「已掌握」区域；可展开或通过状态下拉**恢复为学习中**。
- **总库**：条目**保留**，作为学习记录，**不是删除**。
- **产品规则（PRD §5.1）**：以后 AI **应默认少推荐或不主动推荐**，减少重复打扰。

### 8.3 暂忽略

- **含义**：**暂时不想学**，**不等于**已掌握。
- **本篇**：默认折叠在「暂忽略」区域；可恢复为学习中。
- **总库**：记录保留。
- **产品规则（PRD §5.1）**：以后 AI **默认不主动推荐**该项（与 **§13.5** 方向一致）。

### 8.4 删除（本篇）

- **含义**：从**当前这篇文章**的学习面板移除（误加、重复、不想本篇再出现等）。
- **不等于**已掌握；本篇高亮随 occurrence 移除而消失。
- **总库**：当前实现常**保留**底层 `vocabulary_items` / `grammar_items` 主记录、仅删本篇 **occurrence**（详见 PRD **§5.1「删除」** 与 **`DEVELOPMENT_LOG`** Phase 3.6）。

## 9. AI 推荐与总词库状态 — 产品目标与「当前实现」对照

本节回答常见问题：**「我已经在总词库里标成已掌握了，为什么下一篇 AI 还推荐这个词？」**

### 9.1 产品目标（PRD 怎么说）

- **学习中**：新文章分析中**可以继续推荐**同类表达（与整体推荐策略一致，PRD **§5.1**）。
- **已掌握**：后续 AI **应少推荐或不主动推荐**（PRD **§5.1**）；PRD **§13.5** 亦将「已掌握/已忽略词条后续减少重复推荐」列为**动态反馈与词库联动**方向之一。
- **暂忽略**：后续 **默认不主动推荐**（PRD **§5.1**、**§13.5** 方向）。

### 9.2 当前实现（整文词汇与语法推荐）

- **整文分析**（`/api/analyze-article`）须在请求头携带 **`Authorization: Bearer <当前会话 access_token>`**（与 enrich 接口一致）。服务端用该身份读取 Supabase。
- **词汇**：从您的 **`vocabulary_items`** 中拉取当前 **`mastery_status` 为已掌握或暂忽略** 的 **`normalized_key` + `part_of_speech`**（与库内「两条词汇记录」唯一键对齐）。  
  - 在发给模型的 **user 消息**中附加说明（条数很多时仅列出前若干条示意，**全量仍参与服务端命中**）。  
  - 对模型返回的 **`vocabulary` 列表做后处理剔除**：与上述键**完全一致**的项会被移除；若有剔除，响应里的 **`warning`** 会有一句计数提示。  
- **语法**：从您的 **`grammar_items`** 中拉取当前 **`mastery_status` 为已掌握或暂忽略** 的 **`grammar_key` + `normalized_key`**（与库内「多条语法记录」唯一键对齐）。  
  - 在 **user 消息**中附加说明（条数很多时仅列前若干条示意，**全量仍参与命中**）。  
  - 对 **`grammar` 列表做后处理剔除**；剔除时 **`warning`** 可再追加一句计数。  
  - 模型须为每条语法输出 **`normalized_key`**（可与 **`grammar_key`** 相同，或更细的子键；保存入库时与 **`convertAnalysisToArticleItems`** 一致使用 **`normalized_key` 优先于仅 grammar_key** 的归一化逻辑）。  
- **仍可出现于推荐**：总库为 **学习中**（含 `new` / `learning` / `familiar`）的词条/语法记录；未在「已掌握/暂忽略」表中的键；词汇侧与您已标条目 **词性不同** 的另一条词汇记录；语法侧 **`grammar_key` 相同但 `normalized_key` 不同** 的另一条语法记录。改回学习中后下次分析不再命中剔除。  
- **边界**：若模型给出的键与库内写法不一致，可能偶发**漏剔**；可在预览中手动删除。

### 9.3 与 PRD「未来功能」的关系

- PRD **§13.5** 中**水平自适应提示、profiles 联动**等仍为**后续阶段**；**整文词汇与语法按总库已掌握/暂忽略过滤**已在当前实现中落地（见 **§9.2**）。其它条目以 **`docs/PRD.md`** 与 **`PROJECT_STATUS.md`** 为准。

## 10. 总词库（`/vocabulary`）与总语法库（`/grammar`）

- **维度**：当前登录用户下的**跨文章**汇总。
- **能力（概要）**：搜索、状态筛选、等级筛选、时间分组 Tab、本周复盘小卡、来源文章**精确跳回**某篇 **`/articles/[id]`** 并尽量定位到对应词条/出现位置。
- **状态**：学习中 / 已掌握 / 暂忽略可通过下拉修改；**暂不做**总库整条删除（以 PRD/状态文档为准）。
- **「今日」等口径**：部分 Tab 对「新增 / 再遇」有特殊统计规则（见 PRD **§12.5**）。

### 10.1 同一写法为何可能有两条？

- 词库在数据库里按 **`(user_id, normalized_key, part_of_speech)`** 区分；**同一写法**、**词性/类型不同**时，会对应**两条词汇记录**（技术上要对齐 **归一化键 + 类型**，不能只说「同一个词」）。
- **对外说明**（用户手册、界面提示）：统一用 **「两条词汇记录」**，避免使用「学习档」等内部说法。

## 11. 摘要、阅读问题、深度笔记与外部 AI

- **摘要 / 阅读问题**：在保存**真实 AI 整文分析**结果时写入 **`articles`**；未保存的预览刷新后不保留（以 PRD为准）。
- **深度笔记**：可在词汇/语法卡中粘贴外部 AI 回答或自己的笔记保存至数据库；**不消耗**本应用 OpenAI 调用；需 **008** 迁移（见 **`README.md`** 与 **`docs/DATABASE.md`**）。
- **外部深入解释**：一键复制 Prompt 并跳转 ChatGPT 等，**不入库**；与「补充 AI 解释」（本应用服务端 enrich，仅部分条目类型）区分。

## 12. 删除文章

- 在文章页或文章库中删除文章：删除 **`articles`** 及本篇 **`vocabulary_occurrences` / `grammar_occurrences`**；**保留**长期 **`vocabulary_items` / `grammar_items`** 主记录（与 PRD **Phase 4.1** 一致）。具体提示语以界面为准。
